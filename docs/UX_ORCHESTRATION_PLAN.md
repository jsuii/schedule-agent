# UX与多事件编排：实施计划

目标：一句话的多个事件保持独立字段，经必要澄清后统一确认；默认冲突视图精简，保留硬冲突、替代入口和自定义输入。

诊断：propose_resolution仅接受完整EventInput；失败的多条变更不会保存；只有单条冲突生成case；澄清只在聊天历史中，没有逐事件结构化草稿。原compatible还把相同地点作为唯一兼容条件，不能表达明确包含往返的暂停外出。前端默认展开全部事件属性、全部方案和重复说明。

实现：增加stage_task工具，使用intent_id合并部分事件/关系、持久保存，自动生成窄问题或统一提案。模型理解自然语言，代码不解析中文句子。明确暂停/并行、注意力核实及往返已包含后，使用服务端生成的配对授权支持异地或未知地点，绝不把地点复制给另一事件；缺相关条件继续澄清。明确顺序必须验证。批量内冲突进入同一个case/方案端点。最终提交继续原事务与读回；校验原任务所有intent和关系。默认只显示重叠事实、推荐、采用按钮、其他方案折叠及单行输入；细节按需展开。
