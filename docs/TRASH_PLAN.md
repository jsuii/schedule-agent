# 批量取消与回收站计划

沿用提案/确认/保存点及Calendar SQLite，不另建事件管理架构。

1. 基线及失败回归：单项delete无法表达全范围，多候选强制选一，DELETE永久删除。
2. Calendar兼容迁移deleted_at/deletion_batch_id；所有普通查询、冲突、终态、更新仅活动记录。默认7天，显式有界清理，不加worker。
3. trash服务：精确日期范围快照（完整集合，不受搜索50条限制）、排除/歧义处理、服务器选择修订；确认时重查完整集合及版本，单事务软删除与读回。恢复保持ID、递增版本，验证保留期/来源批次/最终冲突，失败整体回滚。
4. 沿用pending proposals，增加cancel_batch/restore_batch；最新撤销绑定本会话操作ID，普通恢复需清楚显示的确认；UI即时undo以显式点击授权，无冲突直接执行，有冲突仍进入选择。冲突恢复可另选明确可行子集，绝不默默部分提交。
5. 工具让模型理解时间范围，确定性代码处理today/tomorrow/week/date/interval/afternoon；本周周一至下周一（仓库无既有其他定义）。不解析中文意图分类。
6. UI真实列表勾选排除、单次确认、回收站面板、逐条/按批恢复、撤销入口。写前后全量验证保持。
7. 隔离合成A–F/故障注入/并发/HTTP测试，完整回归、独立审查及浏览器；真实DeepSeek新独占账本最多16请求/$0.035，无自动重试/换模型，不改.env。
