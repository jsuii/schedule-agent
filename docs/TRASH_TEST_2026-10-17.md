# 批量取消、回收站与恢复：实际验收

## 根因与实现

原工具propose_delete只接受一个已检索目标，多候选要求点选唯一项，无法表达“取消全部匹配项”；Calendar直接DELETE且没有恢复元数据。模型无法用一个经过验证的操作完成范围取消。此次保留原provider、Agent循环、候选校验、多事件/冲突功能和提案事务。

- Calendar迁移到schema v3：events增加nullable `deleted_at INTEGER`、`deletion_batch_id TEXT`和回收站索引；老记录默认活动。删除批次ID就是执行该删除的proposal/operation ID，无重复元数据列。活动序列化保持兼容。
- 普通get/search/conflicts/slots/count/批量终态排除软删除；原单项delete也改为软删除。ID不变，删除和恢复各递增一次version。回收站单独读取，明确显示删除时间、7天截止时间。
- `trash.py`在同一Store/Calendar上处理范围、排除、来源批次、恢复事实及原子执行，不建立第二套事件数据库。
- `propose_cancel_range`让LLM选择today/tomorrow/week/date/afternoon/interval，代码按每轮当前时区解析。仓库无此前周边界约定，现明确周一00:00至下周一00:00；今天下午12:00–18:00。实际范围必须显示。自定义区间是ISO半开区间；跨午夜事件按现有重叠检索语义包含，下一日零点开始的事件不误入今天。
- 查询完整集合（不受搜索50条上限影响），记录全部ID/version快照。用户勾选或唯一引用排除后服务器重新生成proposal ID、精确选择及count；范围内新项/版本变化均拒绝旧确认，包括已排除项变化。空集合无提案。超过1000项明确要求缩小范围，不截断执行。
- 继续清单必须显式continue_previous=true。新范围默认从全部实际匹配项开始。未解决的“保留谁”歧义不会因空继续消失；只有明确匹配选择或完整checkbox结果可解除阻止。取消清单清除待取消状态，不写事件；新消息使旧提案失效。

## 事务与恢复证据

复用BEGIN IMMEDIATE、SAVEPOINT calendar_write、durable结果回执。取消先在事务内比较完整范围集合，再逐项更新deleted_at/batch/version，最后重新读回所有完整墓碑（包含原数据、版本、批次、删除时间）及活动不可见状态；后续触发器篡改前项也会被发现并整体回滚。恢复验证ID/version/原删除批次、保留期、原字段及最终冲突，整批更新后核验全部字段、版本及回收站消失。任何失败回滚所有事件，失败回执不冒充成功。

恢复冲突显示事件与精确交集；可行子集是明确列表，点击“仅准备恢复可行的N项”生成新的提案，再确认。不会静默部分恢复或修改时间。子集为确定性可行集合，不承诺全局最大集合。

页面“撤销最近删除”是明确的用户动作：绑定本会话指定已提交删除op，校验属于原批次的仍可恢复记录，无冲突则立即原子恢复；有冲突只展示提案和子集选择。成功undo结果幂等回放，不触碰后续新删除批次。**LLM没有确认权限**，自然语言“撤销”仍只调用propose_restore并等待按钮确认。普通回收站单项/批次恢复同样先提案。

## 启动、迁移与清理

启动即幂等迁移，无手工SQL或迁移命令。现8002保留合成结果。重新演示见DEMO，使用新的合成数据库，避免重复场景改变初始状态。迁移以前已被永久DELETE的记录无法凭空恢复；此版本之后的删除保留7天。

清理没有后台定时器，不在普通取消或恢复中发生。到期记录仍可显示但不可恢复；显式函数只删已过期墓碑，每次最多1000条，默认100，重复运行无额外影响：

```python
from scheduler.storage import Store
s = Store('data/your-calendar.sqlite3', 'Asia/Shanghai')
removed = s.calendar.cleanup_trash(limit=100)
```

此函数执行永久清理，应只在明确选择的本地库上调用；本轮仅在隔离测试库执行。未提供页面永久删除按钮。

## 限制

单用户本地应用；回收站为该本地日历共享视图，撤销绑定当前会话。新对话/新cookie不继承旧undo，但可经回收站恢复。范围上限366天、每批1000项；回收站列表前1000项可用对话按标题/删除时间缩小。大清单优先checkbox，减少模型上下文开销；不假称无限规模。无外部日历/真实邀请/后台清理、全局最大恢复子集求解。自然语言仍有非确定性，小样本不保证任意表达，下一步建议离线回放真实工具轨迹与更多排除歧义样例。
